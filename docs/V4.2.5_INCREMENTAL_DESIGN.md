|---|---|---|---|

```

@media (max-width: 560px)   → cssRules.length = 0
@media (pointer: coarse)    → cssRules.length = 0
@media (hover: none)        → cssRules.length = 0
@media (max-height:500px).. → cssRules.length = 0
@media (max-width:700px)..  → cssRules.length = 0
```


```diff
+       if (chordHint && n.midi.length > 1 && clock - n.time < 0.3) {
+         strumChord(n.midi, chordVol());
+       }
      }
```

文件末尾新增两个**模块级纯/准纯函数**（放在 `// ---------- helpers ----------` 之前）：

```js
/* P1-03 和弦提示音：与和弦库「听扫弦」同源（core/audio-engine.js 的 AudioEngine.strum）。
   AudioEngine 是宿主挂到 window 的全局对象，此处只做惰性查找 ——
   · 浏览器：走真实扫弦，与 chord-lib 同音色、共享 master 总线；
   · Node 单测（test/_gp-dom.mjs 没有 AudioContext，也没有 AudioEngine）：
     显式降级为静默并返回 false，绝不让演奏视图在无音频环境抛错；
   · 测试可注入 window.AudioEngine = { strum: spy } 断言发声，产品代码无测试分支。 */
export function chordHintFreqs(midis) {
  return midis.map((m) => 440 * Math.pow(2, (m - 69) / 12)).sort((a, b) => a - b);
}
export function chordVol() {
  const v = Store.settings().backingVolume ?? 0.7;      // 与伴奏音量联动：0.12 ~ 0.30
  return Math.max(0.12, Math.min(0.30, 0.22 * (v / 0.7)));
}
export function strumChord(midis, vol) {
  const AE = (typeof window !== "undefined" && window.AudioEngine) || null;
  if (!AE || typeof AE.strum !== "function" || !Array.isArray(midis) || midis.length < 2) return false;
  AE.strum(chordHintFreqs(midis), "down", vol);
  return true;
}
```

**音量联动口径**（需求 6.3 要求"保留音量滑杆对 strum 的联动"）：
`backingVolume` 默认 0.7 → `chordVol()=0.22`；滑杆 0→1 映射为 `0.12 ~ 0.30`，落在和弦库 `chord-lib.js` 的 `.22~.30` 区间内，**不新增滑杆**（否则与 P2-04「控制区 ≤240px」冲突）。

```
F[53,57,60]  span≤7 : 解 5 个，最大空弦数 0，含空弦解 0      ← 连放宽到 7 都救不了
C[48,52,55]  span≤4 : 解 2 个，最大空弦数 1，含空弦解 1      ← 现状已选中它
```

（理由：`[55,59,62]` 里只有 55/59 是空弦音；若占 2 弦空弦(59)，D4=62 只能在 2 弦 3 品 → **同弦冲突**；若占 3 弦空弦(55)，B3 只能回到 4 弦 9 品 → span=9。真实"开放 G（320003）"包含 6 个音，本产品每个音符只给 3 个音，装不进 span≤4。）

#### 1.7.3 加权打分公式（可实跑，已跑过）

```js
// 评估用克隆求解器（/tmp/voicing5.mjs），与 solveVoicing 同 DFS，仅替换打分：
score(pos) = Σ(f === 0 ? 0 : f + 1)      // 按品数计价，空弦免费
           - 0.8 * opens                  // 开放把位权重：每个空弦 -0.8
           + 0.5 * (maxFret - minFret)    // 跨度过宽惩罚
           + 0.6 * minFret                // 把位越高越惩罚
```

| `maxSpan` | 变化的音集 | 变化的事件 | 典型副作用 |
|---|---|---|---|
| **4（现状）** | **0 / 223（0.00%）** | **0 / 65451（0.00%）** | 无 —— **零收益** |
| 5 | 3 / 223（1.35%） | 3（0.00%） | — |
| 7 | 14 / 223（6.28%） | 16782（**25.64%**） | G 从 `s4f5 s3f4 s2f3` 变成 **`s4f5 s2f0 s3f7`** —— 为凑 1 个空弦把跨度撑到 7 品，**明显更难弹** |

结论：**"增加开放把位权重"在保持 `span≤4` 的前提下无法改变任何输出**（因为 Σfret 最小解在 span≤4 下已唯一最优，且并列解的空弦数无差异 —— 实测 tie-break 增益 0）；要产生变化必须放宽 `maxSpan`，而那会：

1. 直接打破 `test/gp-voicing.test.js` 的 `assertPlayable(maxSpan=4)`（**V-2 / V-3 / V-6 / V-7 全部用它**）；
2. 打破 `test/gp-play.test.js` GP-2 的"每音符 3–4 音 / 音域 40–72"上下文；
3. 产出物理上更难弹的指法（上表 G 的反例）。

#### 1.7.4 本轮建议（需拍板 §5 Q-2）

- **不改 `solveVoicing` 的打分与 `maxSpan`**；
- 新增 `test/gp-voicing-shape.test.js`（或并入 `gp-voicing.test.js`）**固化现状**并登记指标：
  - **V-8 形状固化**：`solveVoicing([48,52,55])` → `s5f3 s4f2 s3f0`；`solveVoicing([55,59,62])` → `s4f5 s3f4 s2f3`；`solveVoicing([45,52,57])` → `s5f0 s4f2 s3f2`（防止后续改动无意回退）；
