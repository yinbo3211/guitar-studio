## 二、客观精度对比（48kHz / 4096 采样窗 / 合成拨弦）

同一份合成信号分别喂给 HEAD 版本（NSDF）与新版（YIN），偏差单位为音分（¢）：

| 场景 | RMS | 旧实现 | 新实现 |
|---|---|---|---|
| E2 正常电平 + 噪声 | 0.0357 | 0.6¢ | **0.1¢** |
| E2 弱电平 + 噪声 | 0.0143 | 1.7¢ | **0.3¢** |
| E2 **远场级**（低于旧门限 0.01） | 0.0045 | **识别不到** | **3.2¢**（±5¢ 绿区内） |
| A2 远场级 | 0.0045 | **识别不到** | **0.8¢** |
| D3 远场级 | 0.0044 | **识别不到** | 8.2¢ → 加低通后 **0.1¢** |
| 静音 / 白噪声 | — | `null` | `null`（无误报） |

### 前置低通的必要性（关键）

差分函数会把通带内全部噪声能量累加。在极低电平 + 宽带噪声下，E2 的偏差是**系统性偏移**（跨帧平滑压不住），不是随机抖动：

| 前置低通 | E2 最差偏差 |
|---|---|
| 无 | 42.3¢ |
| 4 点滑窗 ×1 | 7.9¢ |
| 4 点滑窗 ×2（采用） | **3.1¢** |
| 6 点滑窗 ×2 | 2.1¢ |

滑窗为线性相位，对周期信号只是整体延时常量，周期不变 → 不引入音分偏差；1320Hz（测频上限）处幅度损失 <3%。

## 三、四个问题的根因与修复

### 1. 指针不动

旧代码有一条：

```js
if (Math.abs(cents) > 60) {
  $('#tunerStatus').textContent='';
  $('#tunerNote').textContent='--';
  $('#dialNeedle').style.transform='rotate(0deg)';   // ← 每帧擦回原点
  return;
}
```

只要偏离目标弦稍远，**每一帧都把界面擦回初始态**，视觉上就是纹丝不动，且 `shownCents` 未复位导致下一帧又突跳。

修复：删除该分支，指针由统一的 `glideNeedle()` 按夹紧后的偏差连续转动；偏差再大也保留音名与真实音分值。

### 2. 调音不精确 / 离远识别不到

根因主要是 RMS 硬门限 0.01（参考实现的 medium 档是 0.004，low 档 0.001）——相当于把灵敏度砍掉一个数量级。现改为 5e-4，真正的噪声判定交给噪声门。

### 3. 手动选择弦 + 精准亮绿

点弦按钮 = ①播放该弦参考音 ②**锁定/解锁目标弦**（再点一次解锁）。锁定后判定只针对该弦；绿区改为滞后判定（进 ≤5¢，出 ≥8¢），并给按钮加绿底。

### 4. 手机端和弦转换

根因：`≤860px` 时 `.sidebar` 被 `display:none`，移动端只剩 4 个 tab + 「更多」菜单；而 `MORE_ROUTES` 是**手写常量数组**，漏掉了 V3.1 新增的 `flow`/`plan`/`stats` —— 手机上根本没有任何入口。现改为自动推导，以后新增页面不会再漏。
