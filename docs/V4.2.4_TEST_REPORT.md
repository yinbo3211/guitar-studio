# 五、缺陷与问题清单
按优先级分级：P1 为用户明确要求的修改点（必须改）；P2 为适配与质量缺陷（强烈建议改）。每条缺陷均已定位到具体文件与行号，修改方案见第六节。
## P1-01 逐字歌词功能应移除（用户修改点 1）
•  现状：弹唱页设有彩纸按钮（默认开启），开启后歌词按字/词逐个高亮（karaoke 填色），且显示当前行（26px 粗体）+ 下一行（15px 弱化）两行。
•  实锤位置：gp/play.js L102/205-211（karaokeBtn、karaokeLyrics开关）、L647（lineFillHTML 逐字填色）、gp/karaoke-render.js、gp/karaoke-timeline.js（N-5 中文逐字切分）、i18n 四语文件 play.karaoke 键。
•  影响：逐字切分在中文长句下产生密集 span 节点，也是歌词行叠指板（P2-02）的加重因素。
## P1-02 按钮表情符号歧义且不统一（用户修改点 2）
•  实锤位置：assets/js/i18n 四语言文件（zh-CN/en/ja/ko）的 205–215 行区间：play.start、play.restart、play.karaoke、play.band、play.notes、play.frets、play.metronome、play.songs 八个键均带贴纸符号（播放、循环、麦克风、乐队、喇叭、吉他、鼓、返回等）；暂停状态还有暂停符。
•  风险：不同系统/字体下贴纸符号渲染宽度不一致且可能变形（尤其 Windows 下缺字形时）；与全站其他按钮的纯文字风格不统一。

## P1-03 提示音符音色不像吉他（用户修改点 3 + 增加点 1）
•  现状：提示音由 gp/synth.js Synth.playMidi 按单音触发（play.js L344-349），音色在 gp/voices.js 中合成，非吉他拨弦声。
•  对照：和弦库听扫弦使用 core/audio-engine.js AudioEngine.strum（三角波基音+泛音+指数衰减，六弦 32ms 依次拨响），才是用户认可的吉他声。
•  方案：移除单音提示按钮，新增和弦提示音复用 strum，见 6.3 节。
## P2-01 弹唱页固定 midnight 配色，瀴变全页主题风格（用户适配点 3）
•  实锤证据：宿主主题切至晨曦浅色（--bg #f3efe7）后进入弹唱页，.gp-scope 上 --bg 仍为 #0b0f1a（GuitarPicker midnight 深蓝黑），整页配色突变，与全站 7 套主题体系脱节。
•  根因：gp.css 头部注释明确写明「与宿主 --bg/--text/--accent 令牌隔离，默认使用 midnight」；components.js getVar() 优先读 .gp-scope 变量，宿主主题令牌永远轮不到。

•  范围：i18n/zh-CN.js、en.js、ja.js、ko.js 的 play.* 键（205–215 行区间）及暂停态 ⏸ 文案：纯文字化（开始/重新开始/乐队伴奏/指板/节拍器/返回曲库等）。

## 6.3 去掉提示音符 → 新增和弦提示音（吉他音色）
•  删除：play.js L197–199 soundBtn（音符提示音按钮）与 L344–349 的单音 Synth.playMidi 循环；移除 4 语言 play.notes / play.hint.hitLine 键。
•  新增：控制栏新增和弦提示音按钮（命名建议 chordHint，i18n 键 play.chordHint）；到达判定线时对和弦音符调用和弦库同款吉他扫弦，核心代码：
// 判定线上的和弦音符（play.js 替换原 noteSounds 分支）
if (chordHint && n.midi.length >= 2 && clock - n.time < 0.3) {
  const freqs = n.midi.map(m => 440 * Math.pow(2, (m - 69) / 12)).sort((a, b) => a - b);
  window.AudioEngine.strum(freqs, 'down', 0.3);  // 与和弦库听扫弦同源同音色
}
•  说明：AudioEngine 已挂 window（浏览器环境直接可用），其 master 已汇入 tone-engine 总线，与伴奏共享时钟不冲突；单音音符不再发声。需同时保留音量滑杆对 strum 的联动。
## 6.4 弹唱演奏排版优化（不挡指板，重点）
•  方案 A（推荐，改动最小）：歌词行从画布内移出——移入控制区上方独立单行栏（高度固定 40px），指板面板上移至画布左下且不再被覆盖；当前小节和弦名（gp-bar-chord）并入指板面板标题行，三者分层互不干扰。
•  方案 B（备选）：歌词行保留在画布内，但 bottom 改为指板面板顶部以上（bottom: calc(指板面板高度 + 56px)）且仅限当前行单行，配合 6.1 一起落地。
•  移动端（393 宽）：控制区改为单列两排紧凑按钮 + 音量滑杆收纳为一行，目标控制区 ≤ 240px（释放 ≈ 60px 给舞台）；底部增 env(safe-area-inset-bottom) 内边距。
## 6.5 主题一致性（不破坏主题风格）
•  核心思路：在宿主侧挂载主题令牌到 .gp-scope，优先级高于 gp.css 自带定义——在 gp.css 的 .gp-scope 中把 --bg/--bg-2/--text/--muted/--line/--accent 等改为 var(宿主令牌, 当前值) 回退形式；画布内部（判定线/音符高亮）维持专属高对比配色不变，保证可玩性。
•  浅色主题下二级处理：演奏画布背景允许维持深色（类似视频播放器的沉浸式设计），但侧边、控制栏、按钮、面板必须跟随宿主令牌，避免整页跳色。
•  验收：7 套主题×4 语言×2 分辨率共 56 组截图对比，控制区/侧边配色与宿主一致。
## 6.6 指板和弦精确度（分两层落地）
•  指型层（立即可做）：为 solveVoicing 增加开放把位权重——优先选含空弦品的低把位解（参考和弦库 chord 指法库的 x32010 等标准开放指型白名单），无解时再回退横按；同时标记哑弦使指板图与真实弹法一致。
•  数据层（中期见第七节路线图）：为 231 首补真实调性/BPM/和弦进行。
# 七、yopu.co 谱面精确度调研与借鉴路线
对标站 yopu.co（有谱么，杭州优璞科技）进行了实地调研：其网页版曲库浏览需登录（无头环境下仅返回「请登录」），但通过其公开曲谱页快照与应用介绍已获得完整的谱面规范信息：
•  曲谱格式：纯文本标记语言，{} 分段（主歌/副歌）、[] 内嵌和弦到歌词字，每个和弦标在切入点处而非按小节摆放。
•  元数据：拍号、拍速、选调、原唱调四项完整记录（例如送别：4/4、速度 90、选调 G、原唱调 Bb）、编谱人署名。
•  级数谱模型：主流谱使用级数（1/4/5/6）+ 选调，转调时只换选调不重写谱面——这是其自适应缩放与转调功能的核心设计。
•  内容生态：UGC 社区曲谱 + 网页编辑器（yoopu.me），支持吉他/尤克里里四六弦互转、离线缓存、滚屏跟弹。
