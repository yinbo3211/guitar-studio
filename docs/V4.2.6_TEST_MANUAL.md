# 一、测试概述

本次测试针对六弦工坊（guitar-studio）V4.2.6 版本开展全量回归测试。被测代码为 GitHub 主分支最新提交（commit de8ffca「V4.2.6 收尾补丁包：N-1..N-6 + W-1..W-5」，相对 V4.2.5 基线 0c56374 变更 16 个文件、+1175/-51 行）。该版本依据《V4.2.5 全量测试报告》第八节（N-1..N-6）与第九节（9.1–9.5）落地修复，并附带 511 行增量设计文档（docs/V4.2.6_INCREMENTAL_DESIGN.md，内含对需求源 4 处实测纠正）与 341 行新增测试。

测试于 2026 年 11 月 5 日至 6 日执行，覆盖：单元测试与 lint 门禁（含首次生效的 C8 版本一致性检查）、V4.2.6 六项修复逐项黑盒验证、16 条路由全模块冒烟、弹唱全流程实测（选歌、演奏、暂停恢复、和弦提示音开关、结算）、四语切换（含 V4.2.6 新增词条）、7 套主题切换、移动端 393×852 布局专项、已知 W 项复测。

# 四、新发现问题

## 4.1 BUG-26A（P1）：结算横幅三按钮全部无法点击

现象：弹唱结束后的结算横幅中，「再弹一次 / 曲库 / 练习进度」三个按钮视觉上正常渲染，但鼠标点击无任何响应。桌面端（1280×800）与移动端（393×852）均复现。

取证：以 elementFromPoint 在「练习进度」按钮中心坐标实测，命中元素为背景动画画布 #highway-canvas 而非按钮；getComputedStyle 实测 banner、panel、button 三层的 pointer-events 均为 none。

根因链（gp.css L444-446 及 L509-514）:

.gp-scope .play-overlay { position: absolute; inset: 0; pointer-events: none; }

/* HUD 的 .hud-box / .play-avatar 有恢复 auto 的规则（L453/L458)

.banner / .banner .panel / 按钮均无对应恢复规则 → 全链 none */

根因：.play-overlay 整体设为 pointer-events:none（设计意图为让点击穿透到公路动画画布），HUD 的两个子元素补了 pointer-events:auto 恢复规则，但结算横幅整条链路漏配。按钮的 onclick 处理器本身完好（以 JS el.click() 可正常触发导航至 #/stats），因此这是纯 CSS 层叠遗漏，与 V4.2.6 新改动的返回栏无关（返回栏位于 overlay 之外的控制区，可正常点击）。

影响面：结算后的主操作入口失灵（无法一键再弹、无法从横幅进曲库/进度）。缓解因素：左上角「← 返回」与底部控制区「曲库」按钮均可替代退出，且空格键/重开路径仍可用，故未完全阻断流程，但属明确的 P1 交互缺陷。

修复建议（一行 CSS 即可）:

.gp-scope .banner .panel, .gp-scope .banner .panel .btn { pointer-events: auto; }

注意按 V4.2.6 契约追加在 gp.css 末尾、保持 .gp-scope 前缀、无注释无 @media。建议同时为 S-3 作用域规则补测试断言。

## 4.3 BUG-26C：曲库键名直出现象——结案报告

现象：V4.2.6 首轮测试中曾观察到曲库头部直接显示 i18n 键名（songbook.progress、songbook.stats.practiced、songbook.freeMode 等），刷新页面即恢复正常。

调查过程：以三种操作序列尝试复现（非法路由兜底序列、搜索清空序列、checkbox 与 hash 交错序列）均失败；随后在语言切换往返过程中成功活体复现，并当场取证。

根因（已实锤）：测试工具污染。首轮测试中的一条浏览器控制台取词脚本使用了全局变量名 t（var t = document.querySelector(\u2026)），在全局作用域执行时将 window.t 覆盖为 DOM 元素对象。而六个模块（songbook/song-play/song-practice/play/components 等）的 i18n 取词兜底逻辑均以 window.t 为首选（typeof window.t === \u201cfunction\u201d 检查），window.t 被污染后兜底链直接返回键名，造成大范围键名直出。复现时实测 typeof window.t 为 object（null/DOM 元素），恢复方式为刷新页面（i18n.js 重新挂载 window.t = t）。

结论：正常用户路径下不存在任何触发方式（用户不会在控制台执行全局 var t），因此不构成产品缺陷，结案为测试污染伪缺陷。

附带发现（架构观察项，P4 建议）：全局 window.t 是六个模块 i18n 取词的单一故障点，任何第三方脚本、浏览器扩展或未来的控制台调试都可能令全站文案退化为键名且无自愈。V4.3 建议改为模块静态 import { t } from i18n（ESM 绑定不受全局污染），或至少在 setLang 时重挂一次 window.t 作双保险。

# 九、总结论

V4.2.6 是一次质量较高的收尾补丁：六项修复全部按设计落地且经黑盒实测确认，单元测试规模健康增长（430→443），新增的 C8 版本一致性门禁从机制上杜绝了版本号漂移复发。上轮全部 P1 问题（版本号、emoji、死链、返回可发现性）在 play 模块范围内已清零。

遗留焦点集中在两处：一是结算横幅按钮不可点击（BUG-26A，P1，一行 CSS 可修），二是 emoji 清尾与 HUD 布局两项「范围外」延伸问题，建议随 V4.3 数据层工程一并处理。BUG-26C 键名直出已结案为测试污染，但暴露的 window.t 单点依赖值得在架构层面加固。

综合评定：V4.2.6 可发布，建议热修 BUG-26A 后上线；V4.3 立项清单建议纳入 D-1/D-2/D-3 数据层工程、W-2 孤儿键根治、W-4 HUD 移动端布局与 W-5 可访问名统一。
