## 3.1 共性缺口：乐理术语数据

六模块的缺口主体是乐理术语数据而非界面标签：音阶名（「C 大调」「A 自然小调」）、音程名（「大二度」「纯四度」）、节奏型名（「基础四拍下扫」「三连音」）、和弦进行名（「流行万能 1564」）、把位（「开放把位」）。这些是乐理标准术语，各语种有固定对应译名（C major / Major 2nd / Triplet 等），必须四语化——它们不属于第四章红线的「人名/歌词」。数据层建议两种处理：小表直接内置词条（如音程名、把位）；大表（rhythm-data 节奏型名）可在数据对象上挂 i18n 键，取词时走 T(键)。

# 五、接入规范与样板

## 5.1 tuner.js 模式（R3 已验证的样板）

V4.3.0 对 tuner.js 的接入是唯一完整样板，新模块照此办理，四个要点：

取词走 T()/TF()：所有用户可见动态文案不得出现中文字面量；

监听 gs:lang 重渲染：语言切换事件里刷新本模块 DOM 文本；

只改文本不重建：保住交互状态（如 tuner 的 heard/tuned/picked、scale 的选中把位），避免切语言丢状态；

激活态防复位：模块运行中切语言，主按钮文案按运行态取词（LANG-3 断言先例：调音中保持「停止调音」语义），静态扫描不得覆盖动态运行态。

## 5.2 键名与词条规范

键名格式：模块前缀 + 语义名（rhythm.clearConfirm / scale.pos.open / ear.interval.m2 / plan.diff.basic / game.level.l1 / chords.prog.pop1564）；

四语同步：zh-CN / en / ja / ko 四个 DICT 键集合必须完全一致（i18n-keys.test.js 现有看门会校验）；

占位符：带变量的句子用宿主 tF(key, pairs)（R4 已收敛，勿再写本地 TF）；

预估总量：本工单 ≈138 键 × 4 语 = 552 条翻译，四语键数将从 349 → ≈487。

## 5.3 测试看门（不可削弱）

MOUNT 系列：静态挂载数只增不减（MOUNT-3 看门）；

LANG 系列：新接入模块各加「切语言后 DOM 无中文残留」断言（参照 tuner LANG-3）；

四语键集合一致性校验保持启用；

红线守卫：建议新增一条测试——catalog 的 def.title / def.artist / def.lyrics 字段不得出现 i18n 键引用（防止误词条化）。
