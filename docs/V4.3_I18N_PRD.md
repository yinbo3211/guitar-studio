# 一、摘要

本档为《六弦工坊》V4.3 版本的需求文档，依据 2026-11-08 对 V4.2.7（commit 41c0c86）的全量验收测试与国际化专项审计结果编制。文档回答三件事：第一，V4.2.7 三项热修（弹唱结算横幅可点击 BUG-26A、emoji 收口 BUG-26B、调音器四弦八度误锁）是否真实修复——经单测与浏览器双重复验，结论为全部通过；第二，国际化不完整的量化现状——词条基建健康（4 语 × 271 键零缺键），但静态挂载率仅 9%、JS 层存在 1346 行硬编码中文、切语言后仅导航区联动，形成三处断点；第三，V4.3 的改造方案——以六项需求（R1 移动端语言入口、R2 静态全量挂载、R3 动态文案联动、R4 取词层收敛、R5 内容数据策略、R6 词条补齐）达成四语统一联动，并按两阶段里程碑落地。

## 3.4 移动端语言入口实测

393px 视口（iPhone 主流宽度）实测：.sidebar 容器在 ≤860px 媒体查询下 display:none，而语言按钮的注入逻辑（i18n.js injectEntry）只向 .sidebar 写入，导致移动端语言切换入口物理性不存在。对照主题按钮：theme-switch.js 的 injectEntry 同时注入 .sidebar 与 .topbar 两处，移动端 topbar 可见（display:flex），因此主题切换在手机端可用。两个按钮注入逻辑不对称即为根因，也直接给出修复范式。另实测语言面板本身（openLangPanel 渲染的四语选择浮层）在移动端功能与样式完好——缺的只是可见入口。

## 4.2 R1：移动端语言入口

复刻 theme-switch.js 的双注入范式：i18n.js 的 injectEntry() 在现有 .sidebar 注入之外，增加 .topbar 注入；注入顺序保证语言按钮位于主题按钮右侧（appendChild 时序控制）。同时为两个按钮补 44px 定宽样式，顺带修复实测发现的「主题按钮在移动端被 flex 拉伸至 252px」的视觉失衡。桌面端双入口（sidebar 底部 + topbar 右侧）与主题按钮布局对齐，双端体验一致。

图 5：移动端语言入口改造方案——topbar 尾部主题/语言双按钮并排，44px 定宽

注入目标：.sidebar（现有）+ .topbar（新增），两处去重逻辑相互独立（参考 BUG-08 修复经验：去重判断只查父容器内部）。

视觉规格：44×34px 圆角 9px、1px 描边、图标 18px 线性地球仪 SVG（与现有翻译图标一致）；语言按钮强调色 #D4875A 描边以区分主题按钮。

可访问性：aria-label 复用既有 lang.title 词条（syncAriaLabels 已实现，零新增键）；触控目标 ≥34px 高度满足移动端最低可用标准。

面板行为：点击打开 openLangPanel 既有浮层（已验证移动端可用），选择后即时 setLang 并触发全量联动刷新（R3）。

## 4.3 R2：静态挂载全量化

将 app.html 约 220 行硬编码 UI 文案补挂 data-i18n 属性：页面 title（新增 title 键并在 setLang 同步 document.title）、品牌名、首页 hero 三件套、九大工具卡名称与描述、各视图标题与表单标签、隐私提示等。现有死词条中 home.* / tool.* / common.* 整组可直接激活（键名与语义已按 PRD §7.2 预留）；无对应词条的文案随 R6 补键后挂载。清理策略：挂载完成后运行死词条扫描（对照 data-i18n 属性 + t() 调用），无引用键进入待删清单，避免字典膨胀。

## 4.4 R3：动态文案联动协议

当前 setLang 只刷新静态节点，模块动态生成的文案（toast 提示、状态标签、按钮文本等）不随语言切换。V4.3 建立模块级刷新协议：

取词改造：模块内所有用户可见字符串改为 t(key) 取词，禁止字面量直出（lint 增加中文硬编码扫描规则，纳入 CI）。

刷新协议：各模块在 init 时注册 gs:lang 监听，收到事件后对「当前可见 DOM 的文案节点」执行重渲染；处于非激活视图的模块在视图切换时按当前 lang 惰性渲染（避免全量重刷的性能代价）。

首屏兜底：静态 HTML 中文兜底文案保留（JS 失败时仍可读），i18n init 后按持久化 gs.prefs.lang 覆盖——现有 data-i18n 机制不变。

toast 即时性：toast 类瞬时文案直接用当前 lang 取词，无需监听（生存期短于切换间隔）。

## 4.5 R4：取词层收敛

弹唱模块自带 T/TF 本地实现（回退 window.t、无宿主时返回 key 自身），与宿主形成双轨。收敛方案：宿主 i18n.js 新增 tF(key, pairs) 带参替换导出（占位符 {id} 语义与现有 GP-I18N-3 契约一致，禁止拼接 HTML）；gp/play.js、song-play.js 的本地 T/TF 改为直接引用宿主导出，保留无宿主环境（单测 DOM 桩）的回退分支。GP-I18N 系列测试全部保留并扩展到四语占位符一致性断言。

## 4.6 R5：内容型数据多语策略

songlist-data.js（280 行）、rhythm-data.js（86 行）等属内容型数据而非界面文案：曲名/歌手/歌词/节奏型名称的翻译涉及语义损失与工作量量级，与 UI 文案分轨处理。方案：数据条目支持 { zh, en, ja, ko } 多语字段（缺省回退 zh），取词函数按当前 lang 解析；首批仅覆盖曲名与歌手（列表页直接可见），歌词保持原文并加「原文歌词」标注。此项不计入「UI 硬编码清零」指标。

# 五、交互与视觉规范

## 5.1 语言面板交互

四语选项以 preset-chip 呈现（现有实现），当前语言高亮（渐变底），选择后面板即关；

切换动画：静态节点文本替换无动画（避免整页闪动），模块重渲染局部过渡 200ms；

记忆偏好：沿用 gs.prefs.lang 持久化（store.js），下次进入自动恢复。

## 5.2 双端入口一致性

桌面端：topbar 尾部「主题 · 语言」双按钮并排 + sidebar 底部既有入口，两处行为一致；

移动端：topbar 尾部双按钮并排（44px 定宽），语言按钮位于主题按钮右侧；

触控目标：按钮高度 ≥34px，间距 ≥8px，满足 WCAG 2.1 触控标准。

# 六、技术实现要点

## 6.1 双注入入口（R1 核心）

改动集中在 core/i18n.js 的 injectEntry()，复刻 theme-switch.js 的成熟范式：

function injectEntry() {

const make = (parent) => {

if (!parent || parent.querySelector('.gs-lang-btn')) return;

const btn = document.createElement('button');

btn.className = 'nav-item gs-lang-btn';

btn.style.cssText = 'width:44px;height:34px;flex:0 0 44px;';

btn.innerHTML = GLOBE_SVG;           // 现有地球仪图标

btn.onclick = openLangPanel;

parent.appendChild(btn);             // 后于主题按钮注入 = 右侧

};

make(document.querySelector('.sidebar'));

make(document.querySelector('.topbar'));   // ← 新增：移动端可见

}
