### 0.3 对需求源的实测纠正（4 处）

**纠正 1（N-1 影响面描述失准）**：报告称「应用内关于页/统计口径引用 version.json，会向用户展示错误版本」。实测 `grep -rn "version.json"` 全仓：读取方只有 `sw.js:26`（SW 缓存名派生）与 `server.js:671`（静态白名单），**应用内没有任何关于页/统计页读取 version.json**。**修复仍然必要**（版本号是发布口径 + SW 缓存名来源），但用户不可见——N-1 的真实影响是「发布/SW 缓存口径错误」，不是「用户看到错误版本」。

**纠正 2（N-4 aria-label 表述错误）**：报告 §4 称「移动端顶栏『首页』为纯图标按钮且无 aria-label（无障碍快照中显示为无名按钮）」。CDP `Accessibility.getFullAXTree` 实测：

- 桌面 1280×800：无名按钮 **2 个**——`.gs-theme-btn`（主题切换）与 `.gs-lang-btn`（语言切换），均由 JS 注入、纯 SVG、无文本无 aria-label；
- 移动 393×852：AX 树共 22 个 button，无名仅 **1 个**（topbar 的 `.gs-theme-btn`；sidebar 整体 `display:none` 不进 AX 树）；
- 「首页/调音器/节拍器/…」等 `.nav-item` 与移动端 `.tab` **全部有可访问名**（按钮内含 `<span data-i18n="nav.xxx">首页</span>` 等文本节点，AX 树中名字正确）。

**结论**：报告的「首页无名」不成立；真正无名的是**主题切换与语言切换两个图标按钮**。aria-label 仍值得补（对象修正为这两个按钮），详见 §1.4.3。

**纠正 3（HUD 在 393px 既有横向溢出，决定 N-4 落点）**：实测 gp-song-002 演奏页 HUD 几何——`.play-hud > .col`（计分 + 血条）`x=210.77, w=260 → 右缘 470.77`，而屏幕宽 393、shell 右缘 377。**血条与计分框当前已经约 77px 溢出屏幕右缘**（既有缺陷，本轮不修）。由此推得：N-4 的返回箭头**不得放进 HUD 行**（会把溢出加剧到 101px+），只能落在 HUD 之外。详见 §1.4。

**纠正 4（N-6「不回写」的真实行为）**：用注入式 `gsStore` 实测 `assets/js/gp/state.js`：

- 老用户（`gp:{noteSounds:false}`）：`Store.settings()` → `noteSounds=false, chordHint=undefined`；迁移链 `s.chordHint ?? s.noteSounds ?? true` 求值 **false**（关闭态保留 ✓）；模拟用户切换 `setSetting('chordHint', false)` 后，持久化 `gp = {"noteSounds":false,"chordHint":false}`——**noteSounds 原值保持、未被翻转、未被删除，也没有独立的 noteSounds 写入** ✓；
- 全新用户（`gp` 缺失）：首次任意 `setSetting` 会把整个 `GP_DEFAULTS`（**含 `noteSounds:true`**）整体落盘 → 产生 `noteSounds:true` 孤儿键。这是现状残留（mem.gp 以 DEFAULTS 初始化），**N-6 本轮只做测试不改产品代码**，此残留如实登记（见 §5 待明确 W-2）。

**结论（按主理人拍板：隐藏按钮）**：
- `play.js:768` 整行删除（结算横幅回到 3 按钮：再弹一次 / 曲库 / 练习进度）；
- `song-play.js:17` 的 `'#/locker': 'settings'` 变为**死代码**（play.js 是唯一生产者），一并删除并在注释写明；
- i18n 的 `play.locker` ×4 成为孤儿键 → 四语同删；
- **隐藏 vs 保留的差异**：保留（9.4 方案 A 改映射到 stats）会让用户点进统计页找「外观」找不到，是把假承诺换成了误导导航；隐藏则结算页少一个按钮、零误导。本仓没有任何「外观/储物柜」功能面，隐藏是唯一诚实解。
- **连带发现**：`play.result.coinsHint`（「可到『外观』中使用」/「spend them in the Locker」…）同样指向不存在的功能，属同一假承诺 → 同步改写为中性文案（§1.3.4），不再提「外观/Locker」。

#### 1.1.3 新增 lint C8 检查（`scripts/lint.mjs`）

**落点**：C7 节（L88-97）之后、C3 节（L99）之前。复用 C7 已读出的 `readme` 变量。

```js
/* ---------- 4.5 C8 版本一致性（N-1：version.json = package.json，且 README 含当前版本章节） ---------- */
let c8Bad = 0;
try {
  const pkgV = JSON.parse(readFileSync(path.join(ROOT, 'package.json'), 'utf8')).version;
  const verV = JSON.parse(readFileSync(path.join(ROOT, 'version.json'), 'utf8')).version;
  if (pkgV !== verV) {
    console.error(`❌ C8 版本不一致：package.json=${pkgV}，version.json=${verV}（两处必须同步，SW 缓存名取自 version.json）`);
    c8Bad++;
  }
  /* 鲁棒性口径：README 只要求「当前版本」的标题行存在（^## V4.2.6），
     历史章节（V4.2.1..V4.2.5）允许保留，不要求唯一、不要求其余章节等于当前版本。
     \b 防误匹配（V4.2.6 不会命中 V4.2.60 / V4.2.6x）。 */
  const escV = (s) => String(s).replace(/[.*+?^${}()|[\]\\]/g, '\\$&');
  const headingRe = new RegExp(`^#{1,6}\\s+V${escV(verV)}\\b`, 'm');
  if (!headingRe.test(readme)) {
    console.error(`❌ C8 README 缺少当前版本章节：version.json=${verV}，但未找到形如「## V${verV}」的标题行（历史章节不受影响）`);
    c8Bad++;
  }
  if (!c8Bad) console.log(`✔ C8 版本一致性：${pkgV}（package.json = version.json，README 含 V${verV} 章节）`);
} catch (e) {
  console.error('❌ C8 版本文件解析失败：', e.message);
  c8Bad++;
}
```
