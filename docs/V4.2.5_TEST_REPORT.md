## 3.2 按钮纯文字化（P1-02）
•  演奏页主控条实测（桌面 1280×800 与手机 393×852）均为纯文字：开始/暂停、重新开始、和弦提示音、乐队伴奏、指板、节拍器、曲库——无任何 emoji，四语（中/英/日/韩）键集合保持全等（各 69 个 play.* 键）。

## 3.3 和弦提示音（P1-03）
•  实现与和弦库「听扫弦」同源：判定线上的和弦音符改调 AudioEngine.strum（三角波基音+泛音+指数衰减、六弦依次拨响、共享 master 总线），浏览器真实扫弦、Node 单测环境显式降级静默不抛错（play.js V4.2.5 P1-03 注释，且有 361 行专项测试）。
•  实测：有和弦音符的曲目（如《张三的歌》）控制条出现「和弦提示音」开关；全单音曲目《送别》（gp-song-001，唯一无和弦音符的和弦曲目）按设计隐藏该按钮——这是正确行为，但建议给用户提示原因（N-5）。
## 3.4 主题一致性（P2-01）
•  机制：gp.css 末尾追加令牌接管（--bg 等回退宿主令牌），components.css 加祖先别名绕开同名令牌自引用循环；画布内部判定线/音符高亮保留专用高对比配色。

结论：功能层面「无返回按钮」未复现。但根因分析指向可发现性缺陷——很可能就是用户「感觉没有返回」的来源：
•  演奏页的返回不是行业惯例的左上角「←」箭头，而是混排在底部 7 个功能按钮中的文字按钮「曲库」，与「指板/节拍器/乐队伴奏」等开关按钮视觉同级，极易被当成「去曲库逛」的导航而非「退出演奏」。
•  移动端顶栏「首页」为纯图标按钮且无 aria-label（无障碍快照中显示为无名按钮），图标含义依赖辨识。
•  结算后主按钮文案切换为「再弹一次」，但此前测试中观察到长曲跳转场景下按钮文案与状态偶发不同步（暂停/开始），建议回归时关注。
修改建议见 9.1（左上角统一返回箭头 + aria-label 补全），工作量小、体验收益直接。

# 十、总结论
V4.2.5 是一次质量很高的针对性修复：单元测试从 410 增至 430 且全绿、四项核心缺陷（逐字歌词/按钮符号/提示音色/主题突变）加歌词遮挡全部实锤修复，且附带了罕见的工程级设计文档（对需求源的 5 处实测纠正、穷举证明）。13 个模块浏览器实测零报错，移动端布局显著改善。
遗留面集中在三类：一是修复收尾（结算页 emoji 残留、外观按钮死链、版本号未更新——均为小改动，建议合成一个 V4.2.6 补丁包）；二是返回可发现性（用户本轮报告的直接根因，左上角返回箭头值得做）；三是数据层工程（真实调性/和弦/指型白名单，建议 V4.3 立项）。总体判断：功能基盘稳健，可按第九节方案直接落地。
