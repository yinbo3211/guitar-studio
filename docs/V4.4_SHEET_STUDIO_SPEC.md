## 一、背景与目标

### 1.1 为什么做

六弦工坊现有 231 首弹唱曲库为**内置只读数据**（`assets/js/gp/songs.js` + `songlist-data.js`），用户只能看谱、练谱，**无法录入自己的谱**。社区里大量真实需求是：

1. 网上找到的谱是图片/纸质，想整理成结构化和弦谱，方便手机读谱；
2. 自己扒谱配和弦，希望随手记录、试听验证；
3. 教学场景：老师给学员定制简化谱、改编谱。

有谱么（yoopu.me）验证了「**纯文本标记语言 + 手机友好的和弦谱编辑器**」是最低成本、最高可用性的方案：编辑产物是纯文本（可复制、可备份、可跨端），渲染结果是自适应排版（避免图片谱字体小、缩放不便）。

### 1.2 目标（本期交付）

| 编号 | 目标 | 衡量标准 |
|---|---|---|
| G1 | 提供与有谱么对齐的「新建曲谱」表单 + 和弦谱编辑器 | 表单字段完整覆盖截图 1/2；编辑器覆盖截图 3 全部操作 |
| G2 | 定义本项目自己的曲谱标记语言 gs-chord v1（兼容有谱么/ChordPro 核心子集） | 解析器单测 ≥ 25 项全绿；有谱么示例谱可直接粘贴渲染 |
| G3 | 自制谱可保存、管理、导出 | 本地存储 ≥ 200 首；导出 .txt/.json 可回导 |
| G4 | 自制谱可**试听**（节拍 + 节奏型扫弦 + 歌词高亮） | 任意自制谱 3 秒内可启动试听，速度/调式可调 |
| G5 | 与现有曲库/练习体系打通 | 自制谱出现在弹唱曲库「我的曲谱」；练习时长上报 PracticeStore |
| G6 | 四语 i18n（zh-CN/en/ja/ko）与主题适配 | i18n 红线守卫通过；7 主题下视觉回归无缺陷 |

### 1.3 非目标（本期明确不做）

| 不做 | 理由 |
|---|---|
| 账号、云端同步、社区分享 | 项目隐私红线：全部数据仅存 localStorage，不上传服务器（与 PracticeStore 同口径） |
| 会员/付费墙 | 有谱么的「曲谱编辑是会员功能」横幅不适用；本项目为本地工具 |
| 六线谱（TAB 谱）、五线谱 | 和弦弹唱谱是主场景；六线谱需完整音轨模型，留待 V4.5+ 评估 |
| 拍照识谱（OMR） | 项目已有 OMR 管线仅服务内置数据；对用户照片的通用识谱复杂度过高 |
| 多人协作编辑 | 同上，无云端 |
| 音频对齐打点（卡拉OK 精确对时） | 自制谱无原曲时间轴；M1 按字数均匀分配拍位（见 §5.7），精确打点留待后续 |

### 2.2 本项目超越有谱么的能力（复用现有管线）

1. **可试听的节奏型**：rhythm-data.js 已有 14 个扫弦/分解预设（strum-basic4、strum-pop-a、pick-folk-a……），插入的节奏型不只是文字标注，可用 Tone 引擎实际扫弦发声（F-12）。
2. **与弹唱曲库同一演奏管线**：自制谱桥接为 GP song 定义后，可复用 `gp/accompany.js` 伴奏与歌词卡拉OK 时间轴（`gp/karaoke-timeline.js`，中文逐字切分已在 V4.2.4 修复）。
3. **练习数据闭环**：试听/练习时长进入 PracticeStore，练习统计中心可见「自制谱」模块数据。
4. **和弦闯关式跟练**（远期）：桥接后可挂 grader 评分，本期不承诺。

## 四、数据模型与存储

### 4.1 SheetDoc 对象结构

```js
{
  v: 1,                        // SheetDoc 结构版本
  id: '<uuid>',                // crypto.randomUUID()，同 song-format.js uid()
  kind: 'sheet',               // 类型判别，预留
  title: '七里香',              // 必填，≤60 字符
  artist: '周杰伦',             // 必填，≤60 字符
  transcriber: '',             // 选填，≤30 字符；默认取 gs.prefs.nickname
  key: 'C',                    // 必填，枚举见附录 A-2；决定调性拼写与级数
  originalKey: 'C',            // 必填，同上枚举；仅展示与「演唱调差」换算
  tempo: 70,                   // 必填，40–240 整数
  timeSig: '4/4',              // 必填，枚举 2/4、3/4、4/4、6/8、12/8
  capo: 0,                     // 必填，0–7 品（0=不夹）
  language: '国语',             // 必填，枚举附录 A-3
  style: '流行',               // 必填，枚举附录 A-4
  arrange: '高还原',            // 必填，枚举附录 A-5
  tags: [],                    // 选填，≤3，枚举 + 自定义字符串
  patternId: 'strum-pop-a',    // 默认节奏型，ALL_PATTERNS.id
  text: 'gs-chord 源文本',      // ≤50,000 字符（约 2MB/200 首上限的依据）
  createdAt: <epoch ms>,
  updatedAt: <epoch ms>
}
```

命名对齐说明：字段名与有谱么表单截图一一对应；`tempo/timeSig/capO` 与 GP_CHORD_SONGS 定义的 `bpm/timeSig(拍号文本 timeSigText)/capo` 桥接映射（§4.3）。

### 4.2 存储键与配额

| 键 | 内容 | 写入时机 |
|---|---|---|
| `gs.sheets.v1` | `{ version:1, sheets:[SheetDoc...] }` | 保存/删除/导入时整体写回 |
| `gs.sheets.draft` | `{ doc: SheetDoc(部分), text, savedAt }` | 编辑中 800ms 防抖自动保存 |
| `gs.prefs`（既有键，扩展） | 新增 `nickname`（制谱人默认值）、`sheetEditor:{ fontSize, layout, split }` 编辑器偏好 | 偏好变更时 |

**配额规则（sheet-store.js 强制）**

| 规则 | 阈值 | 行为 |
|---|---|---|
| 曲目数上限 | 200 首 | 到达后「新建/复制/导入」弹出提示：需先删除或导出 |
| 单谱文本上限 | 50,000 字符 | 超限禁止保存，提示「超过 5 万字符，建议拆分为多段谱」 |
| 总容量软上限 | 2 MB | 写入前 `new Blob([json]).size` 预估；超限提示导出备份并清理 |
| localStorage 异常 | QuotaExceededError | 降级内存（对齐 practice-store.js），UI 顶部黄色横幅「浏览器存储不可用，本次会话数据不会被保存」 |
| 损坏数据 | JSON.parse 失败/结构校验失败 | 隔离坏条目并 console.warn，可用部分照常展示（对齐 songbook.js E1 兜底思路） |

### 4.3 桥接：SheetDoc → GP 演奏管线

`expandSheetToGp(sheet, { displayKey, displayCapo })`（sheet-format.js 导出）产出与 `GP_CHORD_SONGS` 同构的定义对象，使 gp/accompany.js、karaoke-timeline.js、transport.js 无改动复用：

```js
{
  id: sheet.id,
  title, artist,
  key: <显示调>, capo: <显示capo>, bpm: sheet.tempo,
  timeSigText: sheet.timeSig,
  chartKind: 'user-chord',          // ★ song-format.js CHART_KINDS 新增枚举值
  source: 'sheet-editor',
  pattern: sheet.patternId,         // 'strum-pop-a' 等，catalog.PATTERNS 兼容
  harmony: { source:'sheet', chords:[[pc,type],...] },   // 见下
  lyrics: [{ time:<秒>, text:<行文本> }...],
  durationSec: <估算>,
  background: { type:'animated', value:'aurora' }        // 复用既有背景
}
```

**harmony.chords 推导规则**：逐行解析和弦标记的字位 → 按 §5.7 拍位映射 → 每小节取**最后落入的**和弦为该小节和弦（与和弦谱演奏习惯一致）；小节无和弦则沿用上一小节；全谱无和弦则回退 `[keyToPc(key),'maj']`（与 harmonize 的兜底同思路）。`[pc,type]` 的 type 通过和弦名解析映射到 `theory.js CHORD_TYPES` 已支持类型（maj/min/7/maj7/m7/sus2/sus4/dim/aug/6/add9/5）；未识别后缀按三和弦处理并在校验面板提示。

**拍位/时间轴推导**：无原曲时间轴，按「每行歌词字数均匀分配到该行拍数」估算：行拍数 = max(4, ceil(字数/4))，逐行累加，秒 = 拍 × 60/tempo。此估算仅用于试听对位（文字滚动与扫弦切换），不参与评分。

**chartKind 扩展的连锁影响**（必须逐点核对）：检索 `CHART_KINDS` 的全部使用点——曲卡徽章、hasRealChart 语义（自制谱返回 false，显示「自制谱」徽章而非「真实谱面」）、评分门禁（自制谱不参与音准评分）、OMR 质量统计（user-chord 无 omr 字段，天然跳过）。新增 switch/if 分支时同步补测试断言。

### 4.4 不修改内置数据

`GP_CHORD_SONGS`、`SONGS`（231 首）为只读内置数据，自制谱**不注入**其中，运行时通过 `sheet-store.list()` 独立提供，songbook 渲染层做数据源合并（F-14）。这样保证升级/清缓存时内置数据与用户数据解耦。

## 五、曲谱源文本标记语言规范（gs-chord v1）

### 5.1 设计原则

1. **兼容有谱么核心子集**：`[]` 和弦标记 + `{}` 格式标记的两大类结构完全一致，有谱么网页版导出的谱可直接粘贴导入（未知标记容错降级为普通文本行，不报错）；
2. **纯文本可手写**：记事本就能写，一屏代码 = 一屏谱；
3. **渲染无关**：源文本不携带字号/颜色/背景，样式全部由渲染层负责（对齐项目「数据与 UI 分离」原则）；
4. **可序列化回写**：解析结果可无损序列化回源文本（编辑器保存的永远是源文本，渲染是派生视图）。

### 5.2 和弦标记

- 语法：`[和弦名]`，插入在**和弦切入点的歌词字之前**（与有谱么一致）。
- 和弦名语法（BNF 简化）：`根音 [修饰] [/低音]`，根音 ∈ {A..G} + 可选 `#`/`b`；修饰 ∈ {m, m7, 7, maj7, sus2, sus4, dim, aug, 6, m6, add9, m7b5, 5}（即 theory.js `CHORD_TYPES` 全集）；斜线和弦 `C/E` 表示低音替换（M1 渲染按斜线前主和弦出指法，低音标注显示）。
- 大小写规范：根音大写、修饰小写；`b`（降号）只跟在根音后（Bb、Eb…），解析器容错 `#`/`♯`/`♭`。
- 示例：`[C]窗外外的麻[C]雀 在[C]电线杆上多嘴` → 渲染为和弦置于歌词上方对齐。

### 5.3 段落标记

- 语法：行首独立行 `{name:主歌}`；快写形式 `#主歌` 等价（`#` 后至行尾为段名）。
- 内置段名快捷项（编辑器插入面板提供）：`前奏`、`主歌`、`主歌 B`、`预副歌`、`副歌`、`副歌 B`、`间奏`、`桥段`、`尾奏`、`自定义…`（弹出行内输入）。
- 渲染：段名独立成行，加粗强调色（CSS token `--sb-section`）。

### 5.4 元信息标记（头部）

表单字段与头部标记**双向同步**：表单改字段 ⇔ 头部标记更新；用户直接改头部标记 ⇔ 表单回显更新。头部标记独立成块写在文本最前：

```
{title:七里香}
{artist:周杰伦}
{transcriber:小明}
{key:C}
{originalKey:C}
{tempo:70}
{time:4/4}
{capo:0}
{rhythm:strum-pop-a}
{meta:语言:国语}
{meta:风格:流行}
{meta:编配:高还原}
{meta:标签:动漫音乐,考级}
```

说明：`{meta:…}` 承载语言/风格/编配/标签等展示性元信息（有谱么的格式标记风格）；解析器对未知 `{xxx:…}` 标记**保留原文**并在渲染中隐藏，导入不丢数据。

### 5.5 节奏型标记

- 段落级：段名行下一行写 `{rhythm: strum-pop-a}` 或快写 `{rhythm:下 下. 下上 下...}`（自由文本型，仅展示不发声）。
- ID 型标记必须命中 `ALL_PATTERNS[].id`（14 个预设，见 §2.2），命中才可试听；未命中 ID 渲染为原文并校验告警。
- 渲染：段落头部显示节奏型徽章（扫弦 D/U 箭头图示或分解弦序图），点击可试听（F-12）。

### 5.6 备注与重复

- 备注：`{comment:女生变调夹 2 品,男生 3 品}` 或行首 `#>` 前缀（`#`已被段名占用，用 `#>` 区分）；渲染为斜体提示行。
- 重复：行尾或段名行写 `{x2}` / `{x4}`；渲染为「×2」徽章；试听时按拍位展开重复遍数（M1 试听只展开 `{x2}`，>2 次折叠为重复标记不展开，上限保护）。
- 副歌跳转记号（`{soc}/{eoc}` 与「回到主歌」）：v1 不做跳转展开，按线性顺序展开重复遍数；在「已知限制」中注明。

### 5.7 词法规则与解析算法

**行类型判定（逐行）**：

| 顺序 | 判定 | 行类型 |
|---|---|---|
| 1 | 整行匹配 `^\{name:...\}$` 或 `^#[^>]` | section（段名） |
| 2 | 整行匹配 `^\{rhythm:...\}$` | rhythm（节奏型） |
| 3 | 整行匹配 `^\{key:|artist:|title:|tempo:|capo:|time:|originalKey:|transcriber:|meta:...\}$` | meta（头部元信息） |
| 4 | 含 `^\{comment:...\}$` 或 `^#>` | comment（备注） |
| 5 | 含 `{x2}`/`{x4}` | 行尾带重复标记的普通行 |
| 6 | 含 `[` 且行内去掉所有 `[...]` 后无剩余字符 | chord-line（纯和弦行） |
| 7 | 其他 | lyric（歌词行，行内可嵌和弦标记） |

**和弦位置提取**：`parseSheetText(text)` 主流程（纯函数，无 DOM）：

```
1. split('\n') → 逐行分类（上表）
2. meta 行 → 更新 meta 字典（重复键后者覆盖，console.warn）
3. lyric/chord-line → tokenize：/(\[[^\]]*\])/ 切分，得到 segments:[{chord?|text}]
4. 字位计算：text 按显示宽度计（CJK/全角=2，ASCII=1，与渲染列宽一致）
5. 拍位映射：行拍数 bars = max(1, ceil(宽/8))（4/4 一行约 8 半角宽一拍起步，timeSig 决定每小节拍数）
6. 输出 SheetAST { meta, lines:[{type, segments, beats, section?, repeat?}], warnings[] }
7. warnings 收集：未闭合 [、未知和弦名（可解析根音但修饰不在 CHORD_TYPES）、未知 patternId、段名重复、capo>7
```

**性能要求**：50,000 字符解析 ≤ 16 ms（桌面 Chrome 参考机）；预览渲染采用 120ms 防抖（对齐 songbook 搜索防抖口径）。

### F-01 新建曲谱表单（P0）

### F-06 和弦行内联想与和弦图预览（P0）

- **触发**：在歌词行输入 `[` → 弹出联想浮层（锚定光标坐标）；继续输入过滤；`↑/↓` 选择、`Enter/Tab` 确认、`Esc` 关闭；`]` 自动补全闭合。
- **候选来源与排序**：
  1. 内置指法库命中（chords.js CHORDS 22 个：C C7 D D7 Dm Dsus2 Dsus4 E E7 Em Esus4 F F#m G G7 A A7 Am Asus2 Asus4 B Bm——渲染指法图）；
  2. 调内理论合成（theory.CHORD_TYPES 全集，任意根音——显示音名无指法图，标注「无指法图」小角标）；
  3. 排序权重：当前选调 diatonic 三和弦（I ii iii IV V vi vii°）> 指法库其他 > 七和弦/挂留/斜线 > 历史使用频次（会话内计数）。
- **和弦图预览**：光标停在某 `[C]` 上（hover/长按）→ 浮层显示指法图（`chords.js renderDiagram`）+ 音名列表；键盘用户 `Alt+↑/↓` 在行内和弦间跳转并显示同一浮层。
- **错误态**：输入 `[Cq` 无法解析 → 浮层红字「无法识别和弦」，`Esc` 或补全 `]` 后保留原文，不强制改正（解析器容错原则）。

### F-07 撤销 / 重做（P0）

- **实现**：快照栈（非 DOM diff）：每次「离散操作」压栈——插入面板项、联想确认、删除选区、粘贴、批量替换（转调另存）；连续键入以 800ms 静默合并为一个快照。
- **容量**：100 步，超出丢最旧；栈内存上限 2MB（超限丢最旧）。
- **交互**：Ctrl+Z / Ctrl+Y（Ctrl+Shift+Z 同 Y）；顶栏按钮禁用态跟随栈状态；**撤销/重做不跨保存边界**（保存时清空重做栈，撤销栈保留）。
- **光标恢复**：每个快照记录光标位置，undo/redo 后恢复光标。

### F-08 草稿自动保存与冲突处理（P0）

- **触发**：编辑画布任何变更 → 800ms 防抖 → 写 `gs.sheets.draft`（含 doc 快照 + text + savedAt）。
- **恢复**：`#/sheetEditor` 无参数进入（新建）→ 存在 < 7 天的草稿 → 弹卡「恢复上次未完成的草稿？《<title>》 <相对时间>」→ 恢复/丢弃；编辑既有谱（带 id）→ 草稿与已存版本 diff 仅在字段 text/meta 不一致时提示「草稿比已保存版本更新（<时间>），恢复草稿？」。
- **冲突**：多标签页同时编辑同一 id：`storage` 事件监听 → 另一页保存了同 id → 当前页顶栏黄条「此谱已在其他标签页修改」+「重新加载 / 覆盖保存」双按钮（last-write-wins 由用户显式选择，不做自动合并）。

### F-09 语法校验与保存（P0）

- **时机**：手动保存（✓/Ctrl+S）、自动保存前（静默）、导入前。
- **阻断级（阻止保存，红色列表）**：文本超 50K 字符；头部 `{title}` 缺失；解析抛异常（理论上不会，容错设计下仅极端结构）。
- **警告级（不阻止，黄色列表 + 行号跳转）**：未闭合 `[`；无法识别的和弦修饰；未命中 patternId 的节奏型；`capo>7`；重复段名（同名段 + 同内容提示合并）；空段落（段名后无内容行）。
- **校验面板**：预览区顶部折叠条「3 个警告 ▾」展开逐条列表，点击跳转到对应行（画布 scrollIntoView + 选中该行）。

### F-10 预览渲染规则（P0）

| 元素 | 规则 |
|---|---|
| 和弦-歌词对齐 | monospace 列宽测量：CJK/全角 = 2 半角宽；和弦名渲染于歌词上方独立行，按字位对齐（与有谱么呈现一致）；同行多个和弦按各自字位放置，重叠时按字位先后错开 0.5em 并收紧字距 |
| 段名行 | 加粗、主题强调色、上方 1.2em 间距 |
| 节奏型徽章 | 段名行右侧：ID 型显示「图示 + 名称」（扫弦 D/U 箭头序列 / 分解弦序数字，复用 rhythm 渲染器），点击试听；自由文本型显示原文 |
| 纯和弦行 | 和弦横向排布，等间距，可整体试听一遍（点击行） |
| 备注行 | 斜体、次级灰色 |
| 重复标记 | 「×2」右上角徽章 |
| 头部信息卡 | 预览顶部：title/artist/transcriber + 拍号·拍速·选调·原唱调·变调夹 + 语言/风格/编配/标签胶囊 + 默认节奏型；样式对齐现有曲卡信息层级 |
| 字号/排版 | 3 档字号；紧凑（行距 1.4）/舒适（1.9）双模式 |
| 移调预览 | ±12 半音即时重渲和弦名（原文不动，仅渲染层移调，刷新/退出即还原）；降号调拼写走 prefersFlat |
| 变调夹视图 | capo = n 时：显示「指法和弦 = 实际和弦 − n」（如实际 C、夹 2 品 → 显示 D 指法）；toggle 在「实际音高 / 指法」两种显示间切换 |

### F-11 转调与变调夹工具（P0/P1）

- **移调预览**（P0）：预览层即时移调，不写回源文本（保证源文本是用户手写真相）。
- **转调另存**（P1）：更多菜单「按当前显示调另存副本」→ 以当前移调值重写整篇源文本和弦标记（含头部 {key}），生成新 SheetDoc（title 自动加「(移调<±n>)」）。实现：逐 segment 调 `chordName(rootPc ± n, type, {preferFlat})`。
- **推荐变调夹**（P0）：表单与编辑器均提供（F-02）；逻辑复用 `suggestCapo()`，偏好易按指法 [0,7,2,9,4]。
- **简化和弦**（P2）：一键将 F→Fmaj7? 不，反向：把难和弦映射为易按替身（F→Fmaj7、Bm→Bm7 等映射表内置 12 条）；渲染层替换 + 源文本不动；本期仅出设计，不实现。

### F-12 试听（弹唱预览播放）（P0）

- **入口**：预览区「▶ 试听」按钮；段落名 hover「从此段试听」；节奏型徽章「试听节奏型」。
- **实现**：sheet-player.js——`core/transport.js` 起拍（BPM = 表单拍速）→ 每小节按当前段落节奏型调 `gp/accompany.js` 扫弦发声（和弦 = 该小节 harmony）→ 鼓机（复用 transport 现成打击轨）→ 歌词高亮（karaoke-timeline 按估算时间轴逐字点亮，复用 V4.2.4 中文逐字切分成果）→ 预览区自动滚动跟随当前行（smooth scroll）。
- **控制条**：播放/暂停、速度 ×0.5/×0.75/×1/×1.25/×1.5（tempo 缩放不改源）、移调 ±（与预览移调联动）、段落跳转 chips（主歌/副歌…直达）。
- **结束行为**：播完自动停止并回顶部；中途切路由 → cleanupModules 停播。
- **数据上报**：一次试听 ≥ 30s 记一条 PracticeSession `{module:'sheetPlayer', durationMs, meta:{sheetId, tempo, patternId}}`；统计中心「练习统计」模块维度自然出现（byModule 已按 module 聚合，无需改统计中心）。

### F-13 我的曲谱（列表与管理）（P0）

- **视图**：曲谱工坊主页 = 「新建曲谱」大按钮 + 搜索框（200ms 防抖）+ 排序（最近编辑/创建时间/曲名，默认最近编辑）+ 标签过滤（语言/风格/编配三行胶囊，选中取交集）+ 曲卡列表。
- **曲卡内容**：title/artist、选调·拍号·变调夹·拍速一行摘要、标签胶囊、「自制」徽章、updatedAt 相对时间；操作按钮：▶ 弹唱、✎ 编辑、⧉ 复制、⇪ 导出、🗑 删除。
- **删除**：二次确认（含标题名称确认文案「删除《x》？此操作不可撤销」）；草稿联动清理。
- **复制**：深拷贝 + 新 id + title 加「(副本)」+ createdAt/updatedAt 重置。
- **空态**：插画 + 「还没有自制谱，点击上方按钮创建第一首」+ 「导入文本」次按钮。
- **搜索**：命中 title/artist/tags/transcriber；拼音首字母搜索为增强项不承诺。

### F-14 曲库联动（P1）

- **songbook「我的曲谱」tab**：难度 tab 行最右追加「我的曲谱」tab（计数徽章 = sheet 数）；选中后曲卡数据源切换为 `sheet-store.list()` 映射出的曲卡（title/artist/tier=自定/单元=自制）；曲卡「开始」进入 F-15 弹唱，「谱」按钮展开显示文本摘要 + 「编辑」入口。

### F-15 弹唱演奏联动（P1）

- 曲卡「▶ 弹唱」→ `sheet-player.js` 全屏弹唱模式（歌词大字逐字高亮 + 当前和弦指法图常驻右下 + 节拍闪灯 + 底部控制条）。

- 麦克风跟弹（期望增强）：复用 Mic 检测弹奏音高做「跟弹正确率」提示——P2 设计预留，本期不做。

### F-16 导入与导出（P1）

- **导入**：曲谱工坊页「导入」→ 弹层 textarea 粘贴 + 可选文件选择（.txt/.json）→ 语法预检（F-09 警告列表预览）→ 确认后进编辑器（不直接入库，先过编辑器人工确认）。.json 批量导入（导出格式回导）逐条校验，失败行跳过并列出。
- **兼容**：有谱么/ChordPro 常见标记（{soc}/{eoc}/{sot}/{eot}/{column_break} 等）M1 容错降级：未知标记保留原文渲染隐藏，不破坏其余内容；已知 ChordPro 子集映射表见附录 B。
